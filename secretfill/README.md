# secretfill

把敏感個資存在 macOS Keychain，表單只留佔位符；等其他欄位都填完，再用這支工具做**檢查 + 取代**，並回報填了哪些、還缺哪些。

值不會出現在任何檔案、argv、shell history 或對話裡。

## 執行模式

```
第一輪：AI（或你）把表單非敏感欄位填完，敏感格留 __phone_number__
第二輪：secretfill fill <檔案>          → 只檢查，列出可填／待補／未登記
       secretfill set <欄位>           → 缺的補進 Keychain（互動輸入）
       secretfill fill <檔案> --write   → 取代，自動備份原檔
```

## 佔位符格式

```
__phone_number__         ← 欄位名見 fields.toml
```

不需要 repo 前綴，因為 **Keychain 的 service 就是命名空間**：`(service, account)` 是
Keychain 項目的唯一鍵，所以另一個專案也可以有自己的 `phone_number` 而不衝突。

| | 值 |
|---|---|
| service | `Happy-Job-Hunting` |
| account | `phone_number`（＝欄位名） |
| label（Keychain Access 顯示的名稱） | `Happy-Job-Hunting phone_number` |

⚠ Keychain **沒有階層**。service 不是可嵌套的群組（不像 KeePassXC 的 Group），
只是項目上的一個字串屬性；寫成 `A/B` 不會變成 `A` 的子節點。而同一個
`(service, account)` 不能有兩筆 —— 所以 `set` 一律帶 `-U` 覆寫。

規則：`__` 包起來，中間只能是英數與單一底線，**不能跨越另一組 `__`**，所以 `__a____b__` 會被正確拆成兩個。

沒在 `fields.toml` 登記的佔位符 **不會被動**，只會在報告裡標成 `? 未登記`，寫入後也會再提醒一次哪些還留在檔案裡。

## 指令

| 指令 | 作用 |
|---|---|
| `fill <檔案>` | 檢查。列出每個佔位符的狀態與出現次數，**不寫入** |
| `fill <檔案> --write` | 取代。原地寫入前自動留 `.bak.YYYYmmdd-HHMMSS` |
| `fill <檔案> --write --out <另存>` | 不動原檔，寫到別的路徑 |
| `set <欄位> [欄位...]` | 存入／更新。由 `security` 自己接 prompt，值不進 argv |
| `list` | 列出登記欄位與「存了沒」。**不顯示值** |
| `list --values` | 連同值一起印出來。**唯一會一次顯示全部值的指令** —— 印之前會先提醒你確認沒有人在看螢幕 |
| `copy <欄位>` | 複製到剪貼簿，不印出值 |
| `get <欄位>` | 印出值（唯一會顯示值的指令） |
| `rm <欄位>` | 從 Keychain 刪除 |

支援檔案格式：`.docx`、以及任何 UTF-8 純文字（`.md`／`.txt`／`.xml`／`.csv`…）。

## 用法

```bash
cd secretfill                      # 在 repo 根目錄底下

# 一次性：存值
uv run secretfill.py set id_number birth_date_roc address_mail

# 表單填好後
uv run secretfill.py fill ~/Downloads/form.docx
uv run secretfill.py fill ~/Downloads/form.docx --write
```

## 出生日期：只存一筆，民國／西元由工具換算

台灣的表單有時要民國年、有時要西元年，格式也各不相同。**只存民國年一筆**，其他寫法全部從它算出來，所以兩種曆法不可能走鐘。

```
儲存：  birth_date_roc          （民國年，唯一一筆真正存在 Keychain 的）

換算：  __birth_date_roc__      84/10/10
        __birth_date_ce__       1995/10/10
        __birth_date_roc_cjk__  民國84年10月10日
        __birth_date_ce_cjk__   1995年10月10日
```

`set` 只接受 `birth_date_roc`；對換算出來的名稱下 `set` 會被拒絕並告訴你該存哪一個。

**輸入格式很寬鬆，輸出一律正規化：** `84/10/10`、`84-10-10`、`84.10.10`、`84年10月10日`、`民國84年10月10日`、`0841010`（身分證式）、`841010` 都吃得下，但輸出永遠是上面那四種樣子 —— 你當初怎麼打的不會滲進文件的格式裡。

擋掉的錯誤：

| 輸入 | 結果 |
|---|---|
| `1995/10/10` | ✗ 存的是民國年，但讀到 1995（**1995 年是民國 84 年**） |
| `84/02/30` | ✗ 不是有效日期 |
| `300/1/1` | ✗ 民國年不合理 |
| `abc` | ✗ 看不出是日期 |

### `__birth_date__` 怎麼判定曆法

裸的 `__birth_date__` 可以用。判定順序是**先看文件裡其他日期欄位怎麼寫**，沒證據就用預設：

| 優先序 | 訊號 | 判定 |
|---|---|---|
| 1 | 文件有西元日期（`2021/09`），沒有民國 | `birth_date_ce` |
| 2 | 文件有民國日期（`民國114年`、`114/03/01`），沒有西元 | `birth_date_roc` |
| 3 | 兩種都有 | **西元（預設）＋警示** |
| 4 | 都沒有 | **西元（預設）**，文件是中文的話**＋警示** |

**⚠ 儲存的是民國年，預設輸出的是西元年 —— 兩件事互不相干。** Keychain 裡永遠只有
`birth_date_roc` 一筆民國年；「預設西元」指的是裸的 `__birth_date__` 要換算成哪一種。

預設之所以是西元：量過這台機器上五份真實應徵表單，**有日期證據的三份全部是西元，
沒有一份是民國**。

判定結果與理由**一定印出來**：

```
📅 __birth_date__ 判定為 **birth_date_ce** —— 文件其他日期是西元（2019/06, 2021/09, 2023/03…），共 6 處
```

`get` / `copy` 沒有文件可讀，一律用預設（西元）。

#### 為什麼不用「中文／英文字數佔比」

量過手上五份真實應徵表單，有日期證據的三份如下（去識別化）：

| 表單 | 中文佔比 | 文件實際用的曆法 |
|---|---|---|
| A（雙語，英文欄位標籤為主） | 25% | 兩位數年份（無法分辨） |
| B | 46% | **西元** |
| C（中文比例最高的一份） | **74%** | **西元** |

**佔比和曆法沒有單調關係，方向甚至是反的** —— 中文比例最高的那份用西元。原因是台灣的表單在每一個欄位標籤下面都印英文小字，所以拉丁字母數量測的是「這個範本有多雙語」，跟填哪種年份無關。

所以**語言已經不是判斷依據**了。中文字元數現在只用來決定要不要警示：中文表單卻沒有任何日期可依據時，就是預設最可能判錯的情況，那時會提醒你改用 `__birth_date_roc__`。

#### 兩位數年份不列入判斷

`26/07/29` 可能是 2026/07/29，也可能是民國26年 —— **本質上無法分辨**，所以只當警示、不當證據。只有這兩種算確定的民國證據：

- 明寫 `民國NN年`
- 三位數年份 `100`–`199`（不可能是四位數西元，也不可能是兩位數縮寫）

#### 空白範本沒有證據

同一份表單 C 的**空白範本**只能吃預設（沒有任何日期可依據，會帶警示），**填好的那份**判得出西元（6 處西元日期，無警示）。所以佔位符要對**已經填過其他欄位**的版本解析 —— 有證據的判定才是可靠的。

表單 C 目前用的是明確的 `__birth_date_ce__` —— 偵測現在也會判對，但明確寫死不會因為之後編輯文件而改變。有證據時就寫明確的名稱。

## 欄位登記表

`fields.toml` **不進版控** —— 欄位組合是個人化的，repo 裡只有 `fields.example.toml`。第一次使用先複製一份：

```bash
cp fields.example.toml fields.toml
```

沒複製就跑指令，工具會直接把這一行印給你。

`fields.toml` 只放**欄位名稱與說明，永遠不放值**。兩種寫法：

```toml
[fields]
emergency_name = "緊急聯絡人姓名"                    # 只有說明

phone_number = { label = "手機號碼",                  # 加上格式
                 format = "09xxxxxxxx（不加分隔符號）",
                 pattern = "09\\d{8}" }
```

| 鍵 | | |
|---|---|---|
| `label` | 必填 | 這個欄位是做什麼的 |
| `format` | 選填 | 給人看的格式提示 |
| `pattern` | 選填 | 正規表示式，用來核對存進去的值 |

`format` 會出現在三個地方：`set` 在你輸入**之前**先顯示、`list` 每一行帶著、`fill` 的報告也帶著 —— 目的是讓你在打字前就知道該打成什麼樣，而不是填完表才發現格式不對。

`pattern` 只**警告不阻擋**：`set` 存完會把值讀回來對一次（不印出值），`fill` 預演時也會對一次。表單格式的例外永遠比規則多，工具沒有資格否決你輸入的東西 —— 它只負責提醒。

⚠ **格式一律宣告在 `fields.toml`，不寫進 `secretfill.py`。** 什麼算合法的電話號碼、身分證字號或日期，是**發表單的那個國家**的性質，不是這支工具的性質。這個 repo 目前這份登記表是台灣的；換一個國家用，改這個檔就好，程式碼一行都不用動。

（`prefix = "..."` 是選用的：設了之後不帶前綴的寫法會當別名解析。預設不設。）

新增欄位＝加一行，再 `set` 一次。登記表擋掉打錯字存成孤兒欄位的情況 —— `set` 只接受登記過的名稱。寫錯的登記本身也會被擋下：不認識的鍵、少了 `label`、或編不起來的 `pattern`，都在載入時就報錯。

### 不是每個欄位都得是秘密

`secretfill` 解的是「**可以被固定填入的資訊**」—— 那些每張表都要填一次、內容永遠一樣、打錯了很麻煩的欄位。敏感只是其中一部分的性質，不是入場條件。學歷的校名與起訖年月不是秘密，但它同樣適合放進來：登記一次，之後每份表單都用 `__edu_bs_from__` 取代，不必再去翻三年前那份舊表。

## 安全設計

- **沒有「搬移」功能，這是刻意的。** 換 service 或欄位名時不提供自動遷移 ——
  遷移必須先把值讀出來再用參數寫回去，那正是 `set` 在避免的事。
  舊項目直接刪掉重存。
- **值不進 argv。** `set` 不自己收輸入，而是把 `-w` 放在 `security add-generic-password` 的最後一個參數，由 `security` 自己開 prompt。`ps` 看不到值，shell history 也沒有。
- **只有 `get` 會顯示值。** `fill` 的報告只有欄位名與次數；`copy` 走 `pbcopy` 不經過終端機。
- **`fill` 預設不寫入。** 要 `--write` 才動手；原地寫入前一定留時間戳備份。
- **有欄位還沒存進 Keychain 時，`--write` 直接拒絕。** 不會寫出半成品表單。
- **產出檔含個資。** 不要進版控、不要貼進對話。`.gitignore` 已擋 `out/`（只留 `.gitkeep`）、常見文件格式（`*.doc`／`*.docx`／`*.odt`／`*.pdf`／`*.rtf`／`*.pages`／`*.xlsx` 等）、`*.bak.*`；輸出建議寫到 `out/`。

## 兩個實作上的坑（都處理了）

**1. `security -w` 有時回傳的不是原文，是 hex。**

值裡含換行、雙引號或反斜線時，`find-generic-password -w` 會印出小寫 hex dump 而不是原文，直接用就會把 `41420a42` 這種亂碼填進表單。工具改成同時查 `-g` —— 它的 `password:` 行在這種情況會帶明確的 `0x` 前綴，據此解回 UTF-8。值含**換行或任何 C0 控制字元／DEL** 會被直接擋下 —— 換行會讓表格跑版，
而控制字元不是合法的 XML character data，填進 docx 會產生 Word 打不開的檔案。

**2. Word 會把你打的佔位符拆成好幾個 `<w:t>` run。**

拼字檢查、修訂記錄、自動校正都會造成 `__id_` / `number` / `__` 被拆到不同 run，對 XML 做字串取代會整個漏掉。工具的做法是把**同一段落**的文字節點串起來比對，命中後把整個值寫進第一個 run（保留原格式）、其餘清空。以段落為界，所以落單的 `__` 不會跨段落配對。

另外 `&`、`<`、`>` 會做 XML escape（地址裡有 `&` 不會炸掉 docx），並補上 `xml:space="preserve"` 讓含空白的值不被折疊。

## 依賴

Python ≥ 3.11（`tomllib`）＋ stdlib，無第三方套件。走 `uv run`。
